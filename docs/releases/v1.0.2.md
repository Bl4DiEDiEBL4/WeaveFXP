# WeaveFXP v1.0.2

Released September 10, 2026.

## Search

- Site Search now uses the server's `SITE SEARCH` command by default, with live results, cancellation, JSON export and local/FXP queue actions.
- Recursive folder scanning is optional. Enable **Recursive folder scan** in the UI or send `recursive: true` through the API to use wildcard/regex and file metadata filters.
- Unsupported server commands report an error instead of silently crawling folders. Cancellation clears pending counters.
- API clients that relied on recursive scanning must now explicitly set `recursive: true`. See [Site Search API](../site-search.md).

## Transfers And Verification

- Local jobs queue per site and share site login and transfer limits. Disconnecting a site pane cancels its queued and running local transfers.
- Queued manual jobs can move up/down. Remove all clears manual jobs without removing races or transferred files; completed archived jobs can also be removed individually.
- Local slot settings live in Local settings. ALL inherits effective Site Manager limits; logs explain the caps determining the actual worker count.
- Local downloads display live SFV folder banners and final COMPLETE/missing markers. CRC32 values calculated during fresh downloads reduce final verification work.
- Same-size skipping, partial-download resume, safe retries and quieter live local-pane refreshes improve manual transfers.

## Races And Mesh

- A shared scoreboard ranks work across races using file priority, measured route speed and rotation between equally scored races.
- Paired slot reservations and shared destination-file claims prevent duplicate dispatch across races. Paused/cancelled work withdraws from scheduling.
- Newly announced races can share released site capacity; independent routes remain runnable and a single race can use all configured slots.
- Cached candidates, warm connections, corrected poll timing and deferred destination setup reduce scheduling overhead and race-start latency.
- In-progress WeaveFTPD 553/X-DUPE replies no longer prove completion. Fresh listings confirm completed files, abandoned uploads can retry, and alternate sources remain available after route failures.
- Permission refusals do not count as completed duplicates. A visible SFV must be parsed before completion markers can establish race completion.

## Interface And Compatibility

- Favorites preserve local/remote pane positions. Editable settings panels have local Save actions.
- Opening the web UI at startup is configurable and remains enabled by default. Windows console/tray handling and UI refresh responsiveness are improved.
- Added persistent color palettes, global SOCKS5/SOCKS5H/HTTP proxy options, cbftp/RaceTrade site compatibility, cbftp JSON import and slftp encrypted UDP support.
- Fixed escaped HTML entities in the cbftp import placeholder.
- Reqfiller is not included.

## Downloads And Upgrade

- `WeaveFXP-v1.0.2-win-x64.zip`: Windows x64.
- `WeaveFXP-v1.0.2-linux-x64.zip`: Linux x64.
- `WeaveFXP-v1.0.2-linux-arm64.zip`: Linux ARM64.
- `SHA256SUMS.txt`: SHA-256 checksums for these archives.

These are self-contained builds; no separate .NET runtime installation is required. Archives contain application files only, never user settings or site credentials.

Stop WeaveFXP before upgrading and back up your existing `data` directory. Extract the application files into the existing installation directory, preserving `data`. On Linux, run `chmod +x WeaveFXP` after extraction.

## Validation

- 124 automated regression checks pass, including loopback FTP integration tests for scheduling, shared limits, duplicates, manual queues and search.
- Release solution build passes with no warnings or errors. Windows x64, Linux x64 and Linux ARM64 binaries are cross-published from Windows.
- Native/recursive search mode switching has been checked in the browser.
- Linux binaries have not been runtime-tested here. Extended real-server soak testing remains necessary; performance superiority over cbftp has not been established.
